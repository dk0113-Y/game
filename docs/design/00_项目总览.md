# 项目总览

## 已确定设计

本项目定位为一个以环境契机和社会接触驱动技术图谱的角色化文明演化策略游戏。

项目不是单纯的 Civ-like，也不是单纯的 CK-like：

- 不采用固定科技树加抽象文明扩张作为唯一主轴。
- 不把家族、人物和继承斗争作为唯一主轴。
- 核心目标是把技术、生产力、环境条件、社会结构和统治集团延续放进同一个策略框架。

当前设计的核心组合为：

- 远古开拓。
- 环境触发科技。
- 生产力革命。
- 时代切换。
- 统治集团延续。
- 政权更替。

玩家控制对象不是抽象文明，而是具体统治集团、家族或权力核心。文明整体可以持续进步，但玩家所代表的统治集团不必然同步获益。

技术与生产力进步不必然等于玩家胜利。新技术可能改变资源分配和阶层力量，进而带来政权危机、继承危机、地方割据或统治集团被架空。

## 当前实现状态

当前仓库是 TypeScript + React 原型，已具备以下基础：

- Vite + React + TypeScript 项目结构。
- `game/core` 与 UI 层分离。
- 六边形地图，坐标采用 axial `q/r`。
- 开拓者可以在相邻六边形之间移动，并受移动点数和地形移动成本限制。
- 已有一格定居/扎营雏形：当前代码中命名仍是 `Settlement` 和 `foundSettlement`。
- 定居后只控制当前地块，不自动控制周边地块。
- 地形数据表达的是潜力和移动成本，不是天然每回合产出。
- `endTurn` 目前提供基础聚落活动产出：每个聚落增加食物和知识。
- 已有 Vitest 测试覆盖六边形、世界创建、地形潜力和定居边界。

## 暂定设计

短期内仍保留当前 React 原型形态，优先验证核心规则，而不是扩大内容规模。

早期玩法术语建议从“建城”调整为“扎营”或“建立营地”。代码层面可后续将 `Settlement` 拆分或重命名为 `Camp` / `Site`，但目前文档中应明确这是设计目标，不表示已经实现。

技术系统暂定采用“契机驱动技术图谱”，而不是固定线性科技树。技术节点是否可见，取决于环境、资源、接触、需求、制度和事件。

时代系统暂定采用阶段切换。进入新时代后，旧时代玩法应折叠为 Legacy / 遗产标签或抽象修正，而不是要求玩家持续微操所有旧机制。

## 后续总路线

推荐后续路线为：

1. 修正早期行动语义，建立行动点 AP 和扎营行为的最小闭环。
2. 建立 Camp / Site 与 Improvement 的数据结构和操作规则。
3. 使用小型手写测试地图验证环境契机。
4. 实现第一版技术图谱，优先验证农业、马匹、水运、冶金和交通。
5. 建立生产力综合指数，并触发第一次生产力革命。
6. 实现时代切换和旧机制 Legacy 折叠。
7. 引入统治集团、阶层力量和政权压力测试。
8. 在规则稳定后推进程序化地图、AI、存档和长期模拟。

## 后续实现建议

- 文档和代码应持续区分“已实现机制”和“设计目标”。
- 当前阶段优先做垂直切片，不要急于扩展完整科技树、完整家族系统或复杂 AI。
- 核心层数据结构应先服务可测试规则，再由 UI 渲染。
- 每次新增系统前，应补充最小测试，避免策略规则只存在于 UI 交互中。

## 未决问题

- Camp、Site、Settlement、City 的代码层级如何划分？
- 第一次生产力革命的最低可玩门槛应设在农业、畜牧、定居、分工中的哪一组组合？
- 政权压力测试从哪个时代开始介入最合适？
