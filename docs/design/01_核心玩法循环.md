# 核心玩法循环

## 已确定设计

早期核心循环围绕“移动探索”和“环境契机”展开：

1. 移动探索。
2. 发现地形、资源或契机。
3. 扎营。
4. 控制一格。
5. 开发设施。
6. 获得资源。
7. 形成生产力。
8. 暴露技术分支。
9. 推动生产力革命。

当前代码只实现了这个循环的前半段雏形：六边形地图、开拓者移动、一格定居/扎营雏形、地形潜力和基础回合产出。开发设施、技术分支、生产力革命尚未实现。

项目的玩法层级会随时代变化。旧时代的操作在新时代不应继续保持同等粒度，而应折叠为 Legacy / 遗产，成为背景能力、修正项或风险来源。

## 暂定设计

中期核心循环暂定为：

1. 聚落扩展。
2. 人口增长。
3. 专业分工。
4. 权力集团出现。
5. 区域治理。
6. 技术和制度联动。

后期核心循环暂定覆盖更高层级：

- 国家阶段：关注统治结构、财政汲取、军队、法令和区域整合。
- 城市阶段：关注城市网络、商业流通、工匠和阶层分化。
- 工业阶段：关注能源、机器、工厂、运输网络和劳资结构。
- 信息阶段：关注平台、数据、科研体系、金融和组织效率。
- 星际阶段：关注行星级资源、轨道基础设施、跨星系后勤和文明延续。

阶段切换参考《孢子》式思路：时代变化后，玩家操作对象和关注层级改变。早期玩家直接移动单位、选择营地；后期玩家管理制度、网络、阶层关系和战略方向。

## 未实现内容

以下内容属于设计目标或后续计划，当前代码尚未实现：

- 完整 AP 行动系统。
- 扎营与营地对象的正式命名和规则。
- 开发设施建设、维护和产出。
- 地图上的资源或 feature 发现机制。
- 技术图谱暴露与研究。
- 生产力指数和生产力革命。
- 时代切换。
- Legacy / 遗产折叠。
- 中后期治理、阶层和制度系统。

## 后续实现建议

- 先把早期循环做成可测试闭环，不要先做完整时代内容。
- 第一版闭环只需要：移动、扎营、控制一格、建一个开发设施、获得资源、触发一个技术暴露。
- Legacy 机制可以先用简单标签表示，例如 `legacy: ["foraging_routes", "clan_camp_network"]`。
- 时代切换 UI 不应只是弹窗解锁，而应改变可操作对象和地图信息密度。

## 未决问题

- 第一版可玩循环中，开发设施是否必须消耗 AP？
- 早期“发现契机”是自动触发，还是需要探索、观察或采集行动？
- Legacy 标签是否只提供加成，还是也可能成为阻碍和统治风险？
- 阶段切换是否允许玩家短暂回看旧层级并做有限调整？
