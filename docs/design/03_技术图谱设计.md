# 技术图谱设计

## 已确定设计

科技系统不应是固定科技树，而应是“契机驱动技术图谱”。

技术节点有三层状态：

- Hidden Tech：隐藏，未触发契机，玩家不能研究。
- Discoverable Tech：已暴露，可研究，但尚未掌握。
- Known Tech：已掌握，可进入应用、扩散或制度联动。

技术发现要区分三个阶段：

- discovery / 发现：看见可能性，通常来自环境、资源、接触、需求、制度或事件。
- research / 研究：投入资源、时间或组织能力，将可发现技术转化为已知技术。
- usage / 应用：把已掌握技术转化为生产方式、设施、单位、制度或社会后果。

技术不是单纯加成。技术会改变生产方式、阶层结构和统治压力。

## 暂定设计

技术发现来源暂定包括：

- 环境触发：接触水域、草原、森林、山地、河流、海岸等。
- 资源触发：发现野生谷物、马群、鱼群、铜矿、铁矿等。
- 接触触发：与其他群体、商人、迁徙者或敌对势力接触。
- 需求触发：饥荒、防御、长距离运输、人口压力等。
- 制度触发：分工、祭司、工匠、官僚、学校、市场等制度能力。
- 事件触发：灾害、战争、迁徙、贸易机会或重大工程。

示例设计：

- 没有野马、马群或草原接触，则驯马分支长期隐藏。
- 没有水域、船匠或海洋接触，则航运分支长期隐藏。
- 发现铜矿或铁矿后，才暴露对应冶金分支。
- 长期人口压力和稳定谷物来源可暴露农业强化相关技术。
- 道路、驿站和车轮技术需要地形、组织和材料共同支撑。

第一批建议验证线：

- 马匹线：草原/马群 -> 驯马 -> 骑乘/畜力 -> 运输和军事变化。
- 水运线：河流/海岸/鱼群 -> 舟筏 -> 航运 -> 贸易和扩张。
- 冶金线：矿脉 -> 铜/铁冶炼 -> 工具/武器 -> 阶层和战争压力。
- 农业线：野生谷物/肥沃地块 -> 栽培 -> 农业剩余 -> 定居和分工。
- 交通线：路线记忆 -> 道路 -> 车辆/驿站 -> 区域整合。

## 当前实现状态

当前代码尚未实现技术图谱、技术状态、发现条件、研究队列或应用系统。现有 `knowledge` 资源可以作为后续研究投入的候选字段，但目前只由基础聚落活动产出。

## 后续实现建议

- 技术节点数据应包含 `id`、`state`、`discoveryTriggers`、`researchCost`、`requires`、`effects` 和 `risks`。
- 触发条件应优先写成可测试的纯函数，避免散落在 UI 中。
- 第一版只需要少量技术节点，重点验证 Hidden -> Discoverable -> Known 的状态流转。
- 技术应用应能影响开发设施、生产力指数、交通能力和政权压力。

## 未决问题

- 技术暴露是否应该完全自动，还是允许玩家执行“观察/试验”行动主动寻找契机？
- Hidden Tech 是否允许通过传闻或接触显示模糊轮廓？
- research 成本应该消耗知识资源，还是消耗人口、时间、材料和组织能力的组合？
- 技术扩散是否需要单独建模？
