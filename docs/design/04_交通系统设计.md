# 交通系统设计

## 已确定设计

交通能力不是单一速度字段，而是：

交通能力 = 工具 × 地形 × 基础设施 × 组织制度。

交通工具不能孤立看待。同一种工具在不同地形、道路质量、组织能力和时代背景下会有完全不同的有效价值。

交通线应至少包括：

- 徒步/骑乘线。
- 轮车/道路线。
- 水运线。
- 机械/现代线。
- 航空/星际线。

当前代码仅实现了地形移动成本和开拓者移动点数，没有实现交通工具、道路、载重、组织制度或多模式交通。

## 暂定设计

平原基础速度倍率暂定如下：

| 方式 | 平原速度倍率 |
| --- | ---: |
| 人无路徒步 | 1.00 |
| 人有路徒步 | 约 1.40 |
| 无路骑马 | 约 1.75 |
| 有路骑马 | 约 2.50 |
| 无路马车 | 约 0.90 |
| 有路马车 | 约 1.90 |
| 有路 + 驿站快马 | 3.50+ |

设计说明：

- 马不是一直高速奔跑，普通长途骑乘主要是 walk + 少量 trot。
- 马车无路时速度优势差，主要价值是载重。
- 道路对马车、汽车等轮式交通增益最大。
- 驿站、高速公路、交通规则等属于组织/基础设施增益。
- 水运应在合适地形上提供高载重和低成本优势，而不是简单等同于高速度。

## 后续字段建议

交通系统可从以下字段开始：

- `mode`：交通模式，例如 `foot`、`mounted`、`cart`、`river_boat`。
- `baseSpeedMultiplier`：基础速度倍率。
- `terrainPenalty`：地形惩罚表。
- `infrastructureBonus`：道路、桥梁、码头、驿站等加成。
- `requires`：技术、资源、设施或制度前置。
- `effectiveEra`：适用时代或开始有效的时代。

后续可补充：

- `cargoMultiplier`：载重能力。
- `maintenanceCost`：维护成本。
- `organizationRequirement`：组织能力要求。
- `riskProfile`：事故、劫掠、天气或补给风险。

## 后续实现建议

- 第一版不需要完整交通系统，可先把当前 `moveCost` 扩展为由地形和交通模式共同计算。
- 道路应先作为地块或边上的基础设施，不要只做全局加成。
- 轮式交通要把速度和载重分开建模，避免马车在无路地形上表现异常。
- 交通能力应影响技术扩散、统治控制、贸易范围和军事投送。

## 未决问题

- 道路是存储在地块上，还是存储在六边形边之间？
- 交通倍率用于单位移动点，还是用于更高层级的区域连通指数？
- 水运是否需要单独的河流边、海岸边和港口节点？
- 载重和速度是否都进入生产力指数？
