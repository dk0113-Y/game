# 地图与地块设计

## 已确定设计

地图采用六边形 axial 坐标 `q/r`。

地块不是天然每回合产出资源。地块表示自然地貌、潜力和可开发条件。

产出来自：

- 营地/聚落自身基础活动。
- 开发设施。
- 人口组织。
- 技术与制度加成。
- 事件或贸易。

当前代码已体现其中一部分：地形有 `potential`，但 `endTurn` 不直接从地形潜力产出资源。当前基础产出来自聚落数量。

开拓者远古时期不是严格意义上的“建城”，设计语义应是“扎营”。扎营后只控制当前一格。周边地块需要后续通过人口、制度、交通或扩张机制纳入控制。

## 暂定设计

建议将 `terrain` 和 `feature` 区分：

- `terrain`：草原、森林、丘陵、河流、海岸等基础地貌。
- `feature`：野生谷物、鱼群、马群、矿脉、密林等可触发契机或开发方向的特征。

当前代码只有 `terrain`，尚未实现 `feature`。

地图制作策略暂定为：

1. 当前阶段使用小型手写测试地图。
2. 中期做程序化地图生成。
3. 后期再考虑地图编辑器。

当前不建议立刻做地图编辑器，因为规则、字段、玩法还不稳定。过早做编辑器会把尚未定型的数据结构固化，增加后续调整成本。

## 当前实现状态

当前地图与地块相关实现包括：

- `Tile` 使用 `q`、`r`、`terrain`、`ownerId`、`settlementId`。
- `Terrain` 包括 `grassland`、`forest`、`hill`、`river`、`coast`。
- `terrainRules` 包括标签、潜力、移动成本和是否可定居。
- 初始世界由固定地形序列生成，不是程序化生态地图。
- 定居后只给当前地块写入 `ownerId` 和 `settlementId`。

## 后续实现建议

- 先增加 `feature` 字段或独立 feature 表，用于触发技术图谱。
- 测试地图应手写，明确包含马群、水域、矿脉、野生谷物等验证点。
- 开发设施应绑定地块，并由 `terrain`、`feature`、技术和人口共同决定可建项。
- 周边控制不应由扎营瞬间自动获得，应通过人口、道路、巡逻、制度或治理范围扩张。

## 未决问题

- `river` 应作为 terrain，还是作为穿过地块边的 feature / edge？
- 海岸地块是否需要同时表达陆地和水域邻接？
- 地块控制是按单格所有权，还是按影响力连续变化？
- 程序化地图生成前，手写测试地图需要多少尺寸和多少场景？
